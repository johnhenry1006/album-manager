# Album Module Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task-by-task.

**Goal:** Implement eight album endpoints with soft deletion, counts, ordered shared media and cover consistency.
**Architecture:** Existing Fastify composition injects album service; services coordinate transactional repositories. Explicit mappers and validators follow existing media conventions.
**Tech Stack:** JavaScript ES modules, Fastify, Prisma/PostgreSQL, Vitest.
**Spec:** docs/superpowers/specs/2026-10-08-albums-design.md

## Global Constraints

JavaScript only. No authentication/current-user invention. Persistence only in repositories. Central error handling. Storage only through injected provider. Deterministic cursor (position, id). Original media immutable.

## Review Focus

- Concurrent member append/removal/cover changes must serialize per album.
- Deleted albums and deleted media must never become usable through membership.
- Duplicate member assignment must retain ordering unless explicitly changed.
- Position overflow and mismatched cursor album must return 400.
- Slug conflicts must return 409 without leaking database errors.
